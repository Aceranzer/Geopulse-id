1. Alur kerja

Tujuan→Pemeriksaan data→Penyiapan data→ Pemodelan→Evaluasi→Penyajian
  1. Tujuan: menentukan kecamatan yang paling perlu diprioritaskan untuk mitigasi banjir.
  2. Pemeriksaan data: menilai kualitas tiap berkas Satu Data Jakarta.
  3. Penyiapan data: membersihkan dan menggabungkan data per kecamatan.
  4. Pemodelan: menghitung peringkat (TOPSIS), lalu mengelompokkan kecamatan (K-Means).
  5. Evaluasi: mengukur mutu klaster dan menguji pengaruh bobot.
  6. Penyajian: website ini, membaca hasil dari folder data/.

4. Cara menghitung peringkat (TOPSIS)

Tiap kecamatan dinilai dengan 8 kriteria. Skor risiko (0–1) makin besar bila kecamatan makin dekat dengan kondisi terburuk dan makin jauh dari kondisi terbaik.

skor = jarak ke kondisi terbaik ÷ (jarak ke terbaik + jarak ke terburuk)

Bobot bawaan dihitung dari data (metode entropi): kriteria yang nilainya paling beragam antar-kecamatan mendapat bobot lebih besar. Jadi bila data berubah, bobot dan peringkat ikut bergeser. Bobot saat ini:

6. Pengelompokan (K-Means)

K-Means mengelompokkan kecamatan yang mirip ke dalam {{ k_final }} kelompok (klaster). Kemiripan diukur dari {{ km.fitur|length }} hal: {% for f in km.fitur %}{{ f }}{% if loop.revindex == 2 %}, dan {% elif not loop.last %}, {% endif %}{% endfor %}. Klaster 0 memiliki skor rata-rata tertinggi, klaster {{ k_final - 1 }} terendah.

Warga terdampak dan kepadatan juga termasuk kriteria TOPSIS. Di K-Means keduanya dipakai lagi supaya pengelompokan lebih menonjolkan sisi penduduk (dampak dan paparan). Karena itu klaster tidak selalu sama dengan urutan peringkat.

Langkah perhitungan

  1. Siapkan data. Fitur yang sangat miring (nilai kecilnya banyak, nilai besarnya sedikit) diubah dengan log, yaitu {% for f in km.praproses if f.log %}{{ f.fitur|lower }}{% if not loop.last %} dan {% endif %}{% endfor %}. Nilai yang ekstrem dipangkas ke batas 5% teratas/terbawah supaya satu kecamatan tidak menarik seluruh klaster.
  2. Samakan skala (standarisasi). Skor bernilai 0–1, sedangkan kepadatan bisa puluhan ribu. Tanpa disamakan, kepadatan akan mendominasi. Tiap fitur diubah menjadi nilai z:
    z = (nilai − rata-rata) ÷ simpangan baku
    Nilai z = 0 berarti sama dengan rata-rata, z = 1 berarti satu simpangan baku di atas rata-rata.
  3. Tentukan {{ k_final }} titik pusat awal secara acak.
  4. Hitung jarak tiap kecamatan ke tiap titik pusat (jarak Euclidean):
    jarak = √[ (z₁ − p₁)² + (z₂ − p₂)² + (z₃ − p₃)² ]
    z = nilai kecamatan, p = nilai titik pusat, untuk tiap fitur.
  5. Masukkan tiap kecamatan ke klaster dengan titik pusat terdekat.
  6. Perbarui titik pusat menjadi rata-rata anggota klasternya. Ulangi langkah 4–6 sampai tidak ada kecamatan yang berpindah klaster.
  7. Pilih hasil terbaik. Langkah 3–6 diulang {{ km.n_init }} kali dari titik awal yang berbeda (seed {{ km.seed }}, jadi hasilnya selalu sama). Yang dipakai adalah hasil dengan total jarak kuadrat terkecil (inersia):
    inersia = jumlah (jarak tiap kecamatan ke pusat klasternya)² = {{ "%.2f"|format(km.inersia) }}
  8. Beri nama. Klaster diurutkan dari rata-rata skor TOPSIS tertinggi ke terendah, lalu diberi nama {% for p in km.pusat %}{{ p.nama }}{% if not loop.last %}, {% endif %}{% endfor %}.

7. Keterbatasan

  • Silhouette {{ "%.2f"|format(metrics.silhouette) }} tergolong lemah: klaster saling berdekatan. Ini wajar untuk {{ n_kecamatan }} kecamatan. Baca klaster sebagai tingkat prioritas, bukan kelompok yang terpisah tegas.
  • Data banjir hanya {{ n_tahun }} dari 12 tahun, dan data 2020 hanya sampai September. Daerah yang jarang melapor bisa tampak lebih aman dari kenyataan.
  • Kepadatan penduduk berasal dari 2019, sedangkan alat peringatan dini dari 2024–2025.
  • Peringkat sangat bergantung pada bobot. Coba ganti skenario di halaman Simulasi.
  • Model belum memakai ketinggian tanah, curah hujan, atau kondisi saluran air.
  • Data rumah pompa sudah dibersihkan dan ada di tabel master, tetapi belum dijadikan kriteria; kriteria tetap 8 sesuai keputusan tim.
